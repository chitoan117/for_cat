# Pre-hardware simulator, dataset and AI preparation

Historical navigation: `CURRENT_PROJECT_STATE.md` · `PRE_HARDWARE_FINAL_BASELINE.md` · `PRE_HARDWARE_HANDOFF.md`.

> **HISTORICAL RC1/RC2 overview:** old counts and narrower tooling descriptions below are retained. Current data/AI commands are `DATA_CAPTURE_WORKFLOW.md` / `AI_EXPERIMENT_REPRODUCIBILITY.md`; current verification is `PRE_HARDWARE_FINAL_BASELINE.md`.

RC2 also provides `app/ai/pipeline.py` and explicit `tools.run_observations --video PATH` for UNKNOWN-mock orchestration. The host suite now exercises an encoded temporary MJPG video through actual OpenCV, not just a fake capture; fixtures are removed and never enter the real dataset. HW_SAFE stays inert, while SIM firmware uses host-tested `command_dispatch.h`. See `PRE_HARDWARE_RC2.md` for current counts and `RC2_ORCHESTRATION_AND_HISTORY.md` for canonical history semantics.

Run from `jetson/`: `python -m tools.run_simulator NORMAL` (other scenario names in `app/simulator/scenarios.json`). Synthetic observations and weights are **SIMULATION VERIFIED** only. `app/simulator/controller.py` models safe boot, daily limits, cooldown, sensor faults, progress/total timeouts and local water hysteresis/recovery; `app/simulator/transport.py` keeps the frozen UART byte format and separates ACK from final result. SimulationSafetyStore models reboot restoration but is **not** ESP32 NVS. Portable C++ policy in `esp32/include/safety_logic.h` compiles in both inert firmware profiles and requires write-ahead persistence before any desired servo-open flag. In RC1, `esp32/test/native_safety.cpp` **executed on the Windows PC** (see `PRE_HARDWARE_RC1.md`), but has not executed on an MCU. C++ and Python are independent policy models; identical results are not proof of hardware equivalence. No pump/servo GPIO exists.

Video replay: from `jetson/`, `python -m tools.replay_video --video PATH --max-frames 300`. Default identity/behavior mocks return UNKNOWN with no fabricated confidence, hence no inferred sessions. An explicit `--predictions PATH` JSON array of frame-indexed identity/behavior/confidence/ROI values drives the temporal engine without training. `VideoFileCameraProvider` distinguishes EOF and offers explicit reset. Replays do not claim live webcam performance.

Data scripts: from project root, `python -m ai.scripts.dataset_report`; `python -m ai.scripts.validate_dataset`; `python -m ai.scripts.import_video FILE --session-id anonymous_1` (dry-run), then `--apply` only after review. Extraction/labeling/splitting similarly require `--apply`; no silent overwrites. Frames are grouped by source session for deterministic train/validation/test split; exact hashes, corrupt images and bounded perceptual near-duplicate warnings are reported. The current dataset is **DATASET_NOT_AVAILABLE**. Do not label/collect unrelated internet images as cat evidence.

`ai.training.prepare` validates nonleaking session splits, saves label map/seed/patience only after real data exists, and reserves test sessions for evaluation. There is no training implementation/runtime/metrics until data and compatible research framework are explicitly selected. `ai.evaluation.evaluate` computes per-class precision/recall/F1, confusion and OTHER_CAT→OWNER_CAT false acceptance only from explicitly supplied real predictions; synthetic unit-test fixtures are **SYNTHETIC_TEST_DATA**, never AI accuracy evidence. Future candidate paths: PyTorch for research, ONNX if suitable, TensorRT only after exact JetPack support is established. None validated.

Experimental behavioral preference trend (`jetson/app/analytics/preference.py`): minimum 3 **distinct** validated-sensor sessions per food (configurable 2–100). Needs reliable dispensed/consumed grams, approach delay and repeat visits. Score is `0.55*consumption_ratio + 0.25*max(0,1-approach_delay/120s) + 0.20*repeat_visit_indicator` averaged across sessions; HIGH ≥0.70, LOW <0.35, else MODERATE. Weights and thresholds are configurable, NOT scientifically validated. Evidence includes sample count, consumption variability, mean delay, leftover and repeat rate. Insufficient data returns no trend; a single image or feeding event never proves what a cat likes.
