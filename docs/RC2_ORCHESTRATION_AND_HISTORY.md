# RC2 orchestration, history and operation-result semantics

> HISTORICAL RC2 implementation checkpoint, not today's verification counts. Current navigation: `CURRENT_PROJECT_STATE.md` · `PRE_HARDWARE_FINAL_BASELINE.md` · `PRE_HARDWARE_HANDOFF.md`. Existing behavior/operation distinctions remain useful; later freshness/atomicity fixes are recorded in `DEFECT_LOG.md`.

`ObservationPipeline` is dependency-injected and synchronous: `start()`, `process_one_frame()`, bounded `run(max_frames,max_seconds,interval,max_failures,stop_when)`, `stop()`. It buffers at most one confirmed active session, reads one frame at a time, sleeps between attempts and never issues a feed command. FastAPI constructs it but does **not** start a hidden live camera loop; explicitly selected offline tools/tests drive it. Optional `tools.run_observations --video PATH` uses UNKNOWN mock models and memory storage by default; no frames/images are persisted by the service.

The default models always return UNKNOWN/no confidence and `/status.ai.state=MOCK`, `trained_model_validated=false`. Injected unvalidated models report NOT_VALIDATED, not AI READY. Tests use fixtures marked **SYNTHETIC_TEST_MODEL**. Camera/EOF and model exceptions keep the API process alive; prediction exceptions report DEGRADED. EOF or explicit stop closes a confirmed visit at the last positive frame, not the later timeout/EOF time; completion_reason describes the boundary. Candidates that were never confirmed yield no session. Timeouts/loop durations use monotonic time; file presentation time is used for replay temporal evidence, with UTC replay-relative timestamps.

Canonical observation truth is typed SQLite `BehaviorRecord` (and its atomic `DrinkingSession` materialization). `RecordRepository.add_visit` atomically persists them, exact retries are idempotent, conflicting IDs never overwrite, and pipeline process namespaces prevent restart counter collisions. `storage/history.py` projects typed visits into the **existing Event-shaped API list**; it does not write duplicate EventStore events. `/behavior` includes confirmed visits; `/drinking-history` projects drinking; `/feeding-history` preserves existing FEED request transitions and additionally projects EATING observations with kind `EATING` (not proof of dispensing). `/events` also projects canonical behavior; daily summary reads the same typed records. Reading endpoints never manufactures observations. All empty routes still return `[]` and unknown grams `null`.

Dispensing and eating are distinct: a camera eating visit is not added as a fabricated successful FeedingSession. Estimated food consumed requires a matched feeding session, validated stable pre/post bowl weights and no known food addition during the interval. Invalid/unstable/missing/negative evidence yields null, not guessed grams. The orchestration defaults to **no** sensor evidence; actual timestamped acquisition is future hardware work.

An optional injected `fusion_context(start,end)` gateway can supply matched session/weight evidence; tests use clearly synthetic values, never live sensors. Eating-duration mean is exposed when known in preference evidence, but the documented experimental score still uses configurable consumption/delay/repeat weights; extra fixtures do not scientifically validate the formula.

Feed retry rule remains UART v1/API v1: ACK → PENDING, final correlated FEED_STATUS resolves it. A disconnect after ACK leaves PENDING; retry with the same Idempotency-Key returns the ledger state and never sends again. `/status` refreshes pending results; `GET /feed/manual/{id}` reads the retained authoritative state and does not secretly resend. Duplicate terminal responses do not create extra feeding history/typed sessions; stale IDs cannot resolve another request. Physical SERIAL mode still blocks FEED_REQUEST locally. No `/servo/open`, `/pump/on` or `/gpio/write` endpoint exists.

SIM firmware now calls the portable feeding policy, uses explicitly synthetic weight/time, memory safety storage and emits PENDING then final FEED_STATUS. HW_SAFE never executes a dispense and returns REJECTED (local reason SAFE_BUILD_ACTUATORS_DISABLED). V1 status byte has no textual reject reason; no incompatible extra bytes are added. Firmware replay storage is a 16-ID fail-closed volatile ledger (full → NACK), **not** power-loss durable command idempotency. Its NVS daily record adapter uses a versioned 25-byte CRC-protected envelope; missing/old/corrupt state fails closed and is not auto-reset. Future real execution requires separately validated sensors, RTC, MCU durable replay and physical output approval.
